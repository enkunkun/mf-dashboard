# PayPay 二重登録の削除スクリプト

## 背景

PayPay 取込（`scripts/paypay-import.ts`）は、取込済みの取引番号を `data/paypay-synced-ids.json` に記録して二重登録を防ぐ。
この記録が Mac と本番コンテナで別々になっていたため、片方で取り込んだ明細をもう片方が未取込と判断し、MF の手動口座「PayPay」「PayPayカード」に同じ明細を再登録した。
2026-10 に 10 件の重複がある（後から入った方の `mf_id` は `19069706…` で始まる）。
crawler は月ごとに MF の内容で DB を入れ直すので、MF 側の明細を消す必要がある。

再発防止として、取込済み ID は本番の記録ファイルに合流させた（2026-10-15、1,042 件）。以後の PayPay 取込は本番だけで行う。

## 目的

指定した月の `/cf` から、PayPay 取込が作った手動口座の重複明細を見つけ、古い方を残して新しい方を MF から削除する。

## 振る舞い

- `tsx --env-file=../../.env scripts/paypay-dedupe.ts --month 2026-10` は dry-run で、削除候補を表示するだけにする。
- `--apply` を付けたときだけ削除する。削除後に同じ月を読み直し、重複が残っていないことを表示する。
- 対象口座は「PayPay」と「PayPayカード」に限る（振替は、どちらかがこの 2 口座なら対象にする）。
- 重複の判定キーは、種別・口座・振替相手・日付・金額・内容とする。
- 同じキーの行のうち、`mfId` の数値が小さい（先に登録された）行を残す。
- 同じ日に同じ店で同じ金額を 2 回払うような正当な重複を消さないため、PayPay CSV に同じ日付・金額・内容の取引が N 件あれば N 件残す。CSV が無いキーは 1 件残す。

## 完了条件

- 判定関数の単体テスト（重複あり、重複なし、対象外口座、CSV で正当な複数件、振替）が通る。
- 本番の 2026-10 で dry-run の候補が 10 件であり、`--apply` 後に重複が 0 件になる。
- crawler の次の run で、DB の PayPay 2 口座の 2026-10 行数が「行数 = 一意な件数」になる。
