# 複数月の再取り込みを 1 回の実行にまとめる

## 背景

`POST /runs {"month":"YYYY-MM"}` は 1 か月ごとにブラウザ起動・ログイン・明細取得・財務分析・web キャッシュ更新を行う。
過去月をまとめて取り込み直すと、グループ全期間の財務分析（約 50 秒）を月の数だけやり直す。
2026-10-14 の実測では 1 か月約 2 分 15 秒のうち半分が分析だった。

## spec

- `POST /runs` は `{"months": ["YYYY-MM", ...]}` を受け付ける。
  - 1 件以上 36 件以下で、各要素は `YYYY-MM` 形式、重複なし。
  - `month`・`allMonths` との同時指定は 400。
  - `categorizeUncategorized`（boolean）は `month` と同じく併用できる。
- 実行は 1 回のブラウザ起動・ログインで、指定順に各月の明細を取り込む（各月は「データベースに保存」ステップとして `{ month }` 付きで記録する）。
- 財務分析と web キャッシュ更新は、全月の取り込みが終わったあとに 1 回だけ行う。
- どれかの月で失敗したら、そこで実行を失敗として止める（取り込み済みの月は DB に残る）。
- `{"month": ...}` の振る舞いは変えない。

## テストリスト

- [ ] server: `months` を受け付けて `startRun({ months })` を呼ぶ
- [ ] server: `months` と `categorizeUncategorized: true` を併用できる
- [ ] server: 空配列・不正な月・重複・`month` との同時指定・37 件以上は 400
- [ ] run: `months` を指定すると各月の `runCashFlowHistoryPhase` を指定順に呼び、分析と web 更新は 1 回だけ
- [ ] run: 途中の月で失敗すると、後続の月と分析を実行しない
- [ ] run: 既存の単月テストはそのまま通る
